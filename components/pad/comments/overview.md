# 댓글 컴포넌트 개요

이 폴더는 게시물 상세 화면의 댓글·답글·수정·멘션 입력 UI를 담당합니다.

- `threaded-comments.tsx`는 `parentId`로 댓글을 트리로 묶어 표시합니다.
- 존재하지 않는 부모를 가졌거나 `parentId` 순환이 감지된 댓글은 유실되지 않도록 최상위 댓글로 표시합니다.
- 댓글 본문은 HTML로 해석하지 않고 React 텍스트로 렌더하며 `@이름` 부분만 시각적으로 강조합니다.
- 답글·수정·삭제는 콜백으로 호출합니다. 생성·수정 콜백에는 본문과 별도로 검증할 `mentionedUserIds`를 전달하고, 새 댓글·답글의 `onCreate`에는 부모 ID와 첨부 대기 `File[]`도 전달합니다. API는 게시물·부모 댓글 관계와 작성자·관리자 권한을 다시 검증해야 합니다.
- 답글 깊이는 화면에서 최대 4단계 들여쓰기로 제한하지만 데이터 자체를 삭제하거나 평탄화하지 않습니다.
- 댓글 작성자와 상위 컴포넌트가 제공한 보드 멤버를 ID 기준으로 합쳐 멘션 후보로 사용합니다. 공백은 `_`로 바꾼 표시용 토큰을 본문에 넣되, 실제 알림 대상 ID는 본문과 분리합니다. 본문에서 토큰을 지우면 해당 ID도 제출하지 않습니다.
- 새 댓글·답글·수정 성공 뒤에는 상위 상태가 서버 응답 DTO로 목록을 갱신해야 합니다.
- `comment-attachment-input.tsx`는 댓글당 최대 4개의 JPEG·PNG·WebP·GIF 또는 MP3·M4A·WAV·OGG·WebM 파일을 대기 목록으로 관리합니다. 이미지는 10MB, 음성은 20MB로 클라이언트 제한합니다.
- 사진 촬영과 음성 녹음은 `components/pad/attachments/media-capture.tsx`를 재사용하며 영상 모드는 노출하지 않습니다.

멘션 알림 API는 전달된 ID가 실제 보드 참여자이며 현재 사용자가 멘션할 수 있는 대상인지 다시 검증해야 합니다.

댓글 첨부 DB 모델과 업로드 API는 Claude의 공용 스키마 인계 뒤 연결합니다. 서버는 파일 시그니처·용량·댓글 접근 권한을 다시 검사하고, 첨부 업로드 실패가 이미 저장된 댓글 본문을 삭제하지 않도록 분리 처리해야 합니다.
